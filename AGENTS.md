# AGENTS.md — Voidrunner

## Headless testing workflow

- Automated tests live in `tests/unit`, `tests/integration`, and `tests/performance`; run `npm test` or the named group scripts. Shared constructors live in `tests/helpers` and must never import a test suite.
- Browser gameplay checks live in `tests/browser`; run `npm run test:browser` against a served runtime. They cover desktop Chrome, Android/Chrome and iPhone/WebKit and always mute sound. Set `VR_BASE_URL` to select the server. Install pinned dev dependencies with `npm ci`, and browser engines with `npx playwright install chromium webkit`.
- `offline-startup.mjs` must keep service workers enabled and use the normal entry URL. It checks decoded opening-screen images, offline resume, report navigation and reconnecting; isolated `startup-probe` tests do not cover these paths. HTTP success alone does not prove an image decoded.
- On macOS, batch cockpit/offline checks isolate both browser profiles and hulls through `tests/helpers/browser-profiles.mjs`. Repeated cold browser launch/teardown cycles in one Node process can stall between cases with no browser running; use `isolateBrowserHulls` for `VR_COCKPIT_HULLS` batches.
- Screenshot capture/comparison and the supplemental frame-time probe live in `tools/playtest/probes`. They are optional diagnostics; the grouped test suites cover the former standalone regression probes. Output must go under ignored `output/`.
- **Clear the Chrome probe profiles before running probes** (`rm -rf /tmp/vr-*-profile`): the deploy update flow reloads the page when a new service worker takes control, which can land mid-poll and reset the session (probes then read a docked, projectile-free world). Fresh profiles also prevent stale cached builds from being tested.
- `__VOID_PRIVATEER__.getRuntime()` returns the **live session object** (added so probes can drive `frame()`/`updateSimulation()` deterministically). Never serialize it wholesale with CDP `returnByValue` ("Object reference chain is too long" — renderer object graphs are circular); read scoped values (e.g. `rt.ships.map(s => s.position)`).
- Probes drive a real session through CDP: headless Chrome (`--headless=new --disable-gpu --enable-unsafe-swiftshader --remote-debugging-port=9333/9334`) + the `window.__VOID_PRIVATEER__` debug hooks in `src/main.js` (`newGame`, `startArena`, `getState`, `getRuntime`, `launch`, `pickTarget`, `projectToScreen`). No test framework; probes exit nonzero on failure.
- Headless rendering runs on SwiftShader (CPU): ~43–44 fps is the software ceiling, so JS-side perf wins are masked in benchmarks — compare relative frame-time changes, not absolute fps.

## Scratch-vector aliasing traps (game.js)

- `vec(array, out)` / `quat(array, out)` return the **same object** as the passed scratch. `updatePlayer` aliases the live player position/velocity/rotation into `this.tmpA/B/C/Q`, and `resolvePlayerCollisions`'s `collide()` wrote the bounce normal into `this.tmpA` — which overwrote the player position with a unit vector, teleporting the ship to ~1 unit from the origin ("crashed into an asteroid, survived, teleported to open space"). Never write into a scratch vector that currently aliases live state; the collision normal uses dedicated `this.tmpCollide`.
- The per-ship AI (`updateAttackAI`/`updateTravelAI`/`resolveShipTarget`/`getShipAvoidance`) is deliberately allocation-free and reuses `tmpD..tmpL`; adding `new THREE.Vector3()`/`clone()` into these hot paths reintroduces GC hitches.

## HUD / UI state rules

- `ui.updateHud()` only runs while flying (`syncRender` gates on `!save.player.dockedAt`, throttled to ~every 42ms). DOM assertions on HUD values (target hint, bars, flight strip) are stale while docked — probes must `launch()` first.
- `navTargetId` must always be a valid `LOCATIONS` key: `buildHudModel` and `showMap` read `LOCATIONS[navTargetId].shortName` unguarded. Never set it to `undefined`; reset to `'shardbelt'` (the save default) instead. Selecting a location sets both `navTargetId` and `currentTargetId`; `launch()` clears the current target and resets nav if it pointed at the exited location.
- The locked target's bracket and lead diamond never hide behind cockpit art: `targetEdge(projection, true)` only returns an edge arrow off screen or behind the pilot, and a point the frame covers gets `behind-frame` (drawn above the instruments with a dark rim). The user found vanishing markers irritating. Comms-speaker and race markers still yield to struts (`targetEdge` default).
- Missile lock is shown Wing Commander style (user request): the target box never changes size or colour; four `.lock-chevron`s slide in from each side (`--lock-gap` 28px → 0) and seat on the box when locked. Don't bring back the shrinking/gold box.
- Planets are nested transparent `BackSide` shells (clouds, halo, outer halo, rings). After launching, the ship sits inside them and every touch raycast hits the shell — they must stay `raycast`-disabled (render-only), or tap-selection always resolves to the planet you just left.

## Flat entity store (entityStore.js)

- `EntityStore` (new module) holds projectile/pickup transforms in Float32Array channels keyed by **slot** (pos/vel/rot + prevPos/prevRot). The sim writes via `setPos/setVel/setPosV/setVelV` and the renderer reads the same channels — there is no per-frame sync array or shared scratch object across the sim/render boundary. Entities carry only metadata (`slot`, id, kind, damage, life); spawns alloc a slot, `cleanupEntities` frees it (free list recycles). `debugSnapshot()` reads positions from the store channels.
- Render meshes for projectiles/pickups are keyed by slot, and liveness is reconciled only when the entity count changes (`shipMeshCount`/`projectileMeshCount`/`pickupMeshCount` compare) — steady state walks and allocates nothing per frame. Ships still use plain arrays but write them **in place** via `tupleInto`/`quatTupleInto` (never `ship.position = tuple(...)` — that allocated ~3 arrays per ship per step). `updateProjectiles`/`updatePickups` run on dedicated `tmpP0..tmpP4` scratches — they must never alias live state.
- New source files must be added to the `sw.js` `cache.addAll` list or the service worker 404s them for returning players.

## Capital hulls and corvettes

- `capitalHulls.js` resolves each hull’s authored mounts into flight coordinates. Weapons, localized damage, target selection, HUD labels and health bars use their kinds and hull values. Only generators, engines and the whole ship cycle on V, right-stick click or the monitor button. All intact parts can take a physical hit.
- The HUD pools small diamonds for generators and engines and dots for other intact parts. Facing comes first. Staggered 5 Hz segment tests use only the target’s current collision mesh, including gaps left by detached pods. Visibility fades over 0.15 s and distance dims the markers from 1,500 to 2,000 units. They yield to cockpit struts.
- In career, 15% of independent-lane traders form Drover convoys with one or two escorts. Pirate raids in the middle and upper fleet-strength bands have a 15% chance of an Ironjaw. A disabled Drover offers boarding. Detached pods spill their share once. Career saves remember damaged traffic at its seeded spawn location, including missing pods and the remaining cargo. A Drover reloads only its intact pods at port. Arena corvettes use level data and never board or surrender. Use `__VOID_PRIVATEER__.spawnCorvette('drover')` or `'ironjaw'` in live flight.

- Display names follow the roster's mythological naming (user): `drover` is **Njord**, its pirate conversion `ironjaw` is **Red Njord**, `caravan` is **Brigid** and its pirate conversion `rookery` is **Red Brigid**. Pirate conversions take the prefix "Red" (Red Talons). Internal ids, saves, models and file names keep the old ids.
- The Caravan and Rookery use their baked frigate paint, exported collision hulls, and hull-specific weapon and damage values. Each engine supplies one third of thrust and each generator restores five shield points per second. Use `__VOID_PRIVATEER__.spawnFrigate('caravan')` or `'rookery'` in flight.
- Tier-2+ independent lanes can spawn a Caravan convoy on 5% of trader rolls. It has two or three escorts and may tow a Drover. The hangar supports two physical repair drones. Pilots can select and shoot them. After carrier loss, deployed repair drones drift inert and targetable for 20 seconds, then self-destruct. Career checkpoints restore the live convoy, drone hulls, stacks and cargo, and the carrier’s launch clocks and surviving escorts. Each stack spills its share once. Losing all engines permits career boarding.
- The Red Njord Barrage (`barge`, missile barge) is the second Njord conversion (`authoring/models/barge`, engineering block raised 1.2 so its roof and keel continue the bridge lines). Six `rack` mounts carry `partBit` and detach like pods (collision groups `rack_N`); the `dish` (fire control) only shows damage. `bargeLaunchers.js` runs it (user design): target speed only slows the lock (`bargeLockRate`: full rate up to 50, four times slower from 100 on), and only line-of-sight rate breaks it, because the tracker cannot follow a pilot crossing fast (full up to 3°/s, lost at 6°/s; at 900 that takes a boosted pass, closer in a cruising one). CHARGING plus the LOCK lamp for 3 s, then `ceil(8·racks/6)` swarm warheads in canisters of four, every 15 s; breaking the lock during the warning reloads in 5 s. Nothing fires inside 250. A pilot closing at 45+ inside 600 draws one unlocked canister per approach (rearms beyond 800). A lost dish halves range and doubles lock time. Its warheads fly exactly like stock swarms so the measured break window holds. Red Njord and the Barrage keep moving on their broadside orbit in range (`standoffCruise` .5 / .3 of top speed, user: strategic movement instead of parking); the Barrage relocates at full speed for 6 s after each salvo. One raid corvette in three is a Barrage (`CORVETTE_TRAFFIC.bargeShare`); Arena level 4 ends on it.
- A ship the player rams recoils by hull size (`resolveShipContacts`: the old 1.5× bounce against a hull of its own size, `1.5·min(1, 2·share)` otherwise), and a hull without engines or a captured prize sheds its drift (`DEAD_DRIFT_DECAY`, 0.5/s). Before that, a ram flung a capital at 1.5× the closing speed and a hull with dead engines coasted out of the fight for good (user bug report on the Barrage).
- Upper-band Red Talon raids can field a Rookery with two Balor escorts on 5% of raid rolls. Career and Arena share the rail sockets, bay damage, launch rate and survivor cap. Carrier loss leaves the fighters in flight. Capital encounters never stack on an active encounter.

## Fixed-timestep sim rules

- The sim runs on a fixed 60Hz accumulator (`SIM_STEP = 1/60`, max 6 steps/frame, `simAccumulator` zeroed while paused/docked). `updateSimulation(STEP, actions)` is the only time the world advances; the renderer interpolates via `prevPosition`/`prevRotation` slots (zero-allocation Float64Arrays, snapshot at the start of each step). Keep the slots out of the save: `saveGame` strips them.
- **Edge actions (hyperdrive toggle, target cycle, missile, scan) must run exactly once per frame in the frame loop — never per sim step.** A multi-step frame double-fires them (toggle engaged + instantly disengaged the hyperdrive) and a zero-step frame (120Hz display) drops them entirely. Axis actions (pitch/yaw/roll/fire) stay per-step. `handleActions` lives in `frame()`, not `updateSimulation()`.

## NPC field steering (fieldCombatNav.js)

- The look-ahead comes from each hull's real turn (`turnModel`: assisted turn rate, slip decay), not only its stopping distance; heavy fighters need ~2.5 s to divert. `predictedClearance` flies the hull's momentum toward a heading (4 chords) and is used for *planning only*: ranking exits (`momentumBonus`, a tie-break on straight-clear corridors) and, in combat, a 10 Hz probe of the live steering line that forces a re-route (`lineBlocked`) when it meets rock. While circling a slow firing target, reserve braking distance for sideways drift using the hull’s turn horizon and its nose-to-velocity alignment. Braking stays on the straight momentum ray: predicted-path braking was optimistic when the pilot did not follow the line and caused wall contacts. Route travel and the approach to a last-known position skip the live-line probe so authored tunnel routes are kept. Once a lost-contact search starts sweeping changing bearings, use the combat turn prediction and local bypasses.
- In combat, test shallow turns between the intended heading and current velocity before committing to a blocker's outside edge. The straight corridor and the predicted turn must both fit with a hull margin. Fly the tested bearing, rejoin a clear pursuit line after the turn, and delay boost until the velocity aligns. If a committed turn still intercepts terrain within a second and the speed limit is falling, start the escape turn under normal braking. Once braking starts, favour a bearing that counters inward drift only when the hull can sweep the turn. An aligned crawling fighter may keep limited escape thrust after its velocity turns outward. Check three departure poses over the next 0.24 s against its oriented collision hull. If no bearing offers usable clearance, report no exit and use the collision normal during physical separation. The round-rock sampler keeps control while its predicted line is clear. On a clear crossing pass the fighter may coast without thrust and turn its guns toward a visible target. For two seconds after rounding cover, a fighter above 75% cruise can continue its clear crossing velocity while tracking a slower opponent. Active manoeuvres, a blocked momentum corridor or ship avoidance veto that coast. Travel clears the combat bend immediately.
- During an active search detour, check the rotating hull when recovering or when its tips can swing faster than its centre travels. Also check recovery turns after a hit. Sample five poses over the next second. If braking clears the turn, keep tracking. Otherwise test progressively steeper departures from the surface before using its normal. A terrain impact damages the ship and delays shield recharge. Reserve incoming-fire dodges and changes to attacker memory for combat hits. The forecast uses its own scratch vectors. Set `TRACE_CONTACTS=1` in the Arena probe to record the command and the preceding two seconds for every counted terrain contact.
- Steering uses a centre-cell query. Large obstacles whose outer surfaces reach the planned flight corridor must also be included, even when their centres lie outside the query. Drifting pieces update the oversized list when the grid refreshes. Cache a conservative distance to each candidate once per steering update. Predicted rays include their displacement from the hull before skipping unreachable obstacles. Search and travel need the same large-obstacle clearance as attack. Thin wreck plates use diagonal mesh rays as well as axial rays. Graph edges, entry legs, string-pulling and live handoffs check the centre and eight wing rays. Reaching a waypoint radius cannot skip a corner. Keep a shared graph that has an entry for the hunter. On entry failure, build around both endpoints when they fit.
- Run `node --import ./tests/helpers/offline-imports.mjs tools/playtest/probes/npc-routes.mjs` for armed, fixed-step duels by site, tier and seed. It measures time below 30% and 10% of cruise, halts below 5% lasting half a second, hard brakes, speed within two hull lengths, terrain contacts, firing and hits. Each halt includes two seconds of approach samples. The probe reports exclusive command counts on slow 60 Hz ticks. The default includes an armed duel and a separate lost-contact search with a holding ship. Use `MODES=duel` for the historical panel and `MODES=search-hold` for the search fixture. `TIMING_ONLY=1` omits command attribution. `OUT` selects the JSON file, `SEEDS` selects matched scenarios, and `PAIRS=6` measures AI time per simulation step with twelve fighters.
- Measure changes with `node --import ./tests/helpers/offline-imports.mjs tools/playtest/probes/cliff-duel.mjs` (terrain brakes/stops/bumps per ship-minute near shardbelt rock; `ROOT=<checkout>` runs another copy for an A/B). Single scripted tests (`tactical-scrapes`, `terrain-maneuvers`, `asteroid-field` tunnels) are sensitive to planning changes; run them with the benchmark.
- Combat pathfinding (`fieldRoadmap.js`): a per-field roadmap (free-space lattice + Shardbelt bores + open wreck interiors, edges checked across the hull width) built in ~4 ms slices from `updateSimulation` (Arena staging requests it at the site start; career on the first blocked pursuit) and one A* per blocked pilot to the nearest node that sees the target in range, string-pulled. `combatRouteWaypoint` engages after `ROUTE_BLOCKED_DELAY` of blocked line of sight and drops the route as soon as the target is in sight; the attack AI then skips terrain/ace manoeuvres, and `combatThrottle` burns long clear legs. Career searches route to the last-known point the same way. Career and Arena keep identical visibility/search rules (`combat-mode-parity.test.mjs`).
- Field tactics share career and Arena sensors. For damaged shields, forecast the hull’s assisted turn, drift and braking into a hull-clear shadow. Share five cover headings per fixed step across pilots, including replans. Recheck the shadow and entry from the latest sighting before committing. All tactic legs use the forecast’s stopping-speed cap and the live terrain limit. Cover holds at most 5 s, the whole break at most 14 s, with a 30 s cooldown and the per-target attempt cap. A second fighter may flank while a partner has the target in weapon range. Update the endpoint from sightings once per second. Recheck the pressure pilot’s track, gun range and clear line throughout the flank. Count arrival only across its bearing, in range and with a clear shot. A concealed ambusher can wait up to 4 s or step out along a checked firing lane. Wing orders take priority and wingmen never ambush. Surrender, capture and other transfers of control release the tactic and its slot. Arena opponents stay in the sortie outside the career traffic radius.
- Radio uses the shared 9 s chatter gap. Mission lines own the channel until their last page clears. A wingman retries a blocked tail warning while the pursuit lasts. Cover calls require half a second in real shadow, flank calls require arrival and ambush calls require an actual forward shot. The Arena probe records each commitment, completion, exit reason and unfinished attempt at cutoff. Keep both the stationary and returning-fire panels.
- Wreck sections (`shape: 'wreck-mesh'`) are measured by their mesh once a ray reaches the box (`rayDistance`): the box encloses hangars and torn midsections and pinned pilots at 0 km inside them. Asteroids keep the box path. A far, clear approach uses the closing burn (`distance > max(2.6·preferred, 650)`, keeping `BURN_RESERVE` (35 %) of the capacitor); closer burns raised terrain contacts in `cliff-duel`.
- A magrail pilot matches a firing pass only when its selected mount has energy, has cooled down, and has a settled intercept inside its trigger cone with a clear shot. Magrail and mortar pilots resume pursuit through reloads, including finishing passes. Hull braking, overshoot and combat manoeuvres still set physical speed limits.
- Measure Arena combat with `node tools/playtest/probes/arena-combat.mjs` (live runtime, every site's first wave, pilot holding still): first shot, line of sight in range, shots/hits per minute, stuck/limited/search time, bumps. Use `PILOT=engage` for a moving pilot returning fire or `PILOT=defend` for a stationary pilot returning fire. Runs vary; compare two or more. Keep `cliff-duel` at parity when changing the controller.
- `boost-reversal` is the deliberate flip-and-burn (the user likes it); `immelmann` is the speed-keeping alternative for mid-range fits. Its pull time comes from the hull (`immelmannPull`, ~0.65·π·v/a): thrust only acts along the nose, so a faster pull bleeds speed to a near stop like the flip. Career spawns roll loot affixes onto guns while Arena uses base items, so mode-parity tests must spawn before setting `arena`.

- Fuel is gone (user: less micro-management; 0.8.2px). The afterburner draws energy (`stats.burnEnergy` = base reactor output + base capacity / `BURN_SECONDS` (15), so a full capacitor alone feeds ~15 s; reactor/capacitor upgrades lengthen it, Comet Tail `burnEnergyMultiplier` .7). With an empty capacitor the burn keeps its doubled turn authority but not the speed, so a missile break always works (`unpowered` trials in `missile-flight.mjs` keep the core window). NPC burns draw the same energy: closing/route burns keep `BURN_RESERVE` (35 %), evasive boosts need `BURN_MINIMUM` (10 %). A race drive meters its own charge and costs no energy; a centred gate refunds `centerBoostReward` seconds of burn. The dock's `ordnance` service (formerly `fuel`) restocks missiles and ammunition; the own monitor's second cell shows THR. Old saves drop `player.fuel`; saved fuel distress calls load as the `power` (dead reactor) variant.
- The player's missile cue is a one-shot "break now" (`breakCueTime` in `weaponFlight.js`): the middle of the rack's measured dodge window plus `BREAK_REACTION` (0.3 s) plus the device's audio output latency (`audio.outputLatency()`, ≤ 0.2 s). Once per salvo; the approach pips stop after it. Pilots reacting within 0.2–0.5 s dodge every seeker and swarm warhead in the harness.
- Dodging is tuned by measurement (`tests/helpers/missile-flight.mjs`, user request: single missiles were too hard to shake). Seekers fly 200 at 40°/s, swarms 220 at 45°/s, both with a 600-unit terminal phase: a break defeats a seeker from about 0.5 to 1.75 s before impact and a swarm salvo from 0.5 to 1.5 s, and the four swarm lanes share one outcome. Turn rate and cone barely move the window; speed and terminal range do. `breakCueStart` follows the measured window.
- Torpedoes fly at 90 and can be shot down by the pilot's guns (`TORPEDO_HIT_RADIUS`, casing shield 12), never an ally's (`torpedoThreatensPlayerSide`). `ordnanceMarkers.js` draws a red diamond on each hostile torpedo within 2 km plus a lead dot for the slowest selected gun, and an orange ring (on screen) or edge chevron for every round homing on the player. `#break-cue` (`.screen-break`) flashes BREAK twice over the own-ship monitor with the audio break cue (user: on the monitor, short and quick, not over the 3D view), for pilots playing without sound.
- Mission hostiles start in sight (`visibleSpawnPosition`): bounty targets, encounters, salvage ambushes, claim disputes and fresh distress raiders (±30°) move to the nearest clear, visible bearing at the same range when rock or wreckage hides them.
- NPC gunnery misses on purpose, and close (`npcGunnery.js`): each projectile burst is on target with `onTarget` (0.6, equal for every tier so skill only shows in precision/tracking) or lined up `NEAR_MISS_RING` (1.5–2.5) target radii off the hull, walking around it during the burst. The offset scales with target size and distance; beams keep their slip model. Measure with `tools/playtest/probes/npc-aim.mjs` (weaving pilot, `MOVE=still` parked): hit / near miss / wide per tier. The user wants frequent, visible near misses, not sharper NPC aim.
- Drive damage uses the same wear rules in career and Arena. A crippled fighter retains 50% of top speed and loses boost. Use round percentages for drive penalties. Arena opponents keep fighting until destroyed. Surrender, fleeing after surrender and boarding belong to career flight.

## Equipment progression (equipmentCatalog.js)

- Forward guns and missile launchers have separate, category-specific sockets. There are no mount sizes. Use the gun or launcher index for its muzzle anchor, fire group or magazine. Move incompatible legacy gear to storage with its ammunition.

- The user asked for equipment to feel like a space RPG: tier and rarity must be recognisable. Tier is the big axis (`TIER_CURVE`: damage 1 / 1.3 / 1.65, system bonus 1 / 1.4 / 1.8); rarity adds a smaller primary gain plus affixes (`EQUIPMENT_RARITIES`: common/uncommon/rare/epic/named, where `named` is shown as Legendary). Keep a new tier's common part above the previous tier's rare; `equipment-progression-balance.test.mjs` checks the ladder and `equipmentRating` ordering.
- Records store `affixes` plus parallel `rolls` (0–1); the resolved value is `lerp(range, floor + (1-floor)·roll)` with the rarity's floor. Records without rolls resolve at 0.5. Affixes either multiply a resolved modifier (`mod`) or add a tier-scaled ship effect (`bonus`). Legendary traits live in `NAMED_EQUIPMENT` (`mods`, `weapon` overrides, `scale`, `effects`); hardware without an entry rolls epic instead.
- Stock torpedoes deal 360 damage to every hull, carry a 20-unit blast and pierce only corvette and capital-ship shields on direct and splash hits. Player, wingman, NPC and frigate torpedo racks use the target’s actual speed and relative line-of-sight rate for their locks. The torpedo definition sets `fullLockSpeed` / `zeroLockSpeed` and `fullLockAngularRate` / `zeroLockAngularRate`.
- Projectiles carry the rolled flight definition as `hitWeapon`, so shield/hull multipliers and traits apply at impact; `critEvery` counts shots per mount (`critShotCounts`), `siphon` refunds energy through `siphonWeaponEnergy`. NPC and player fits share all of this.
- Scarcity is a user requirement: dealers stay the dependable source, drops are rare and special (`RARITY_WEIGHTS` ≈ 88 / 9.2 / 2.2 / 0.45 / 0.15; common survival ~16%). Don't raise colour rates to make loot "feel" better; make the moment better instead (receipt priority, reward sting, crate beams). Drop luck: `equipCareerItems` passes `(regionTier-1)·0.25 + {veteran .15, ace .35}`; `rollRarity` multiplies each grade's weight by `(1+luck)^rank`. Legendaries are unique per player (`ownedLegendaries`). Drones keep 18% survival.
- Affix roles (energy-limited fights decide value): Overcharged = damage, Efficient = sustained fire, Rapid = burst only, Siphoning = sustained fire for accurate pilots (it should edge out Efficient above ~50 % hits). Affix ranges and system bonuses use round ends (5 % steps, 10–20 flat). Legendary traits sit at roughly +25–30 % effective power; a situational trait (jam, blast) also gets +10 % damage. The laser turret is auto-aimed support: keep its damage per energy below forward guns but useful (~2 vs ~3.5).
- Signature colour (`equipmentSignature`): a legendary's own, else the best-rolled specialising affix (`signature` on the affix). It becomes `weapon.tint` → `projectile.tint` (bolt/beam/flash/impact; render pools key on tint) and the icon accent. Icons: `itemEquipment.mjs` tier parts and `itemGlyphs.mjs` `TIER_PAINT` produce `id@2`/`id@3` sprites; glow pixels carry accent codes so `itemIcons.js` recolours them at runtime. Audition tints on the FX review's Signature row.

## Arena Run screens (arenaRunView.js)

- `renderArenaRun(ui, save)` builds every Arena Run preparation view (hulls, wingmen, rewards, ready room, fitting, result); `GameUI.showArenaRun` only mounts it. Keep the `data-ui-command`/`data-run-action`/`data-run-value`/`data-run-key`/`data-run-index` attributes: the click handler, controller focus and tests drive the run through them. Styles live in the `arena run` section of `station-ui.css` (console tokens, `.sx-btn` keys scoped to `#arena-panel`); the former `.run-*` rules in `style.css` were removed — don't reintroduce run styling there.
- Reward offers fit the ship (`rewardFitScore`, `pickForFit` in `arenaRun.js`): a reward scores by its rating over what it replaces (empty bay 1.5, downgrade < 1), with boosts for what the build lacks (power when gun draw exceeds 1.5× reactor, shields under 120, a launcher when no rack is fitted). Each pool picks a weighted draw among its top three; downgrades only appear when nothing better fits. An empty gun socket scores as an empty bay for a gun, and an empty missile socket does the same for a launcher. A replacement uses a socket of its own type. Arena runs start without mining drones; PDC/repair drones are survival rewards for hulls with bays and are written into the live loadout (`loadoutFor` returns a copy).
- Reward cards and fitting spares show a "Ship after" block (`runShipTotals` in `arenaRunView.js`): the whole-ship totals that change (firepower, reactor-limited sustained fire, weapon draw, turret fire, missile load, shield, hull, recharge, energy, speed, turning), old → new with the difference, plus the gun-draw-versus-reactor budget (amber when over). The user could not judge rewards from item stats alone. Phones show the three most important rows, new value and change only.
- Arena wingmen cannot be destroyed: the hit that would kill one floors its hull at 1 and powers it down for the rest of the level (`powerDownRunWingman`: dark, unarmed, not a target, orders not re-applied). The level-clear records each wingman's `hullFraction`; `recoverRun` repairs it by the pilot's rule (+30%, hard +10%, repair service or skipped draw +50%, full before the finale), and the next level spawns it at that hull with full shields.
- Coloured Arena rewards must be real records (`runRewardItem` creates `eq-arena-…` records for any grade above common), so card colour, modifiers and stats always agree. Hull silhouettes take their viewBox from the contour points (`profileBox`), not `profile.min/max`.

- Levels author `groups` in `arenaRun.js`. `arenaBattle.js` keeps group, radio, launch and objective state in the live session. Version-3 checkpoints still restart the same level. A group arrives when at most one hostile survives or 60 seconds pass since the previous group (45 seconds in Act I). Authored timers and hull thresholds can also call a group. The first eligible trigger wins, with at least 15 seconds between authored arrivals. The whole group must fit before the five-second warning. The Cut loose duel reserves the field for its lone Morrigan. Earlier acts allow three hostile fighters, Act V four and two aces. Capital hulls and carrier-launched fighters use their own limits. Each warning uses the stage reinforcement entry, the existing hollow marker and one call in the shared radio gap. A warning fixes the arrival point. Recheck terrain and capital hulls on arrival and use the nearest clear offset if blocked.
- Destroy the primary, intercept the Drover before its jump (both engines out also wins), or defend it until the jump. The timer follows the ship’s distance. With a working engine either Drover keeps at least half cruise. Each defended engine retains one hull point. The friendly Drover takes hull damage but never turns hostile. ## Performance architecture

- The obstacle grid (`game.js`) uses a numeric packed cell key (3×13 bits) instead of `"x,y,z"` strings — the string version was the top GC/CPU cost (DDA checks 26 neighbours per cell). Keep it numeric; cell coords must stay within ±4096.
- Instanced asteroids/debris upload only drifting pieces per frame (`addUpdateRange`); static rocks are composed once. Don't recompose all instances every frame.
- Auto power mode is adaptive (`frameBudget.js`): touch devices start at 30 fps and promote to 60 after 12 s of headroom (desktop follows the measured refresh); two overloaded 2 s windows (missed callbacks, too few *delivered* frames, or expensive frames) drop back and start a 30 s cooldown. `reset()` (pause/map/visibility) keeps the cooldown, `restart()` (dock/launch) also returns to 30, `clear()` (power setting changed) forgets everything; stopped spectator battles only `suspendSampling()`. The 30 fps gate tolerates refresh-scaled timestamp jitter: a sub-millisecond tolerance produced 50 ms gaps on WebKit. Battery/Smoother stay fixed 30/60.
- Graveyard wrecks are batched per finish and index-clipped to the camera only inside the WebGL submission (a private draw range restored in `finally`); raycasts, other cameras and an exception mid-draw always see the full geometry. Wreck models stream two at a time, nearest first, each publishing on its own; until one arrives (or offline, never cached) a flat-shaded derelict made from its collision triangles stands in, so visuals and colliders always agree. The service worker fills field wrecks in the background only during quiet flight, never with Save-Data or 2G.
- Shipping assets are generated at build: `npm run build` packs the field wrecks to `.glb.gz` and the Lancer/Torsas hulls (`tools/assets/pack-hull-textures.py`, Pillow pinned in `tools/assets/requirements.txt`) into `dist` and fails on any mismatch. Never check generated `.glb.gz` or packed hulls into the source tree; the checkout serves raw `.glb`. Hull textures keep full resolution (2K variants visibly softened lettering and plating).
- iOS station GLBs skip decoding normal/roughness maps (`omitDetailMaps`) because `simplifyAppleMaterial` drops them anyway; decoded images are shared by content hash, never their `THREE.Texture`.

## Sound design pipeline

- `audio.js` is the mixer and event engine; `soundEvents.js` defines every event as layers over bank ids; `soundBank.js` lists the recorded bodies and imports the generated `soundBankManifest.js`; `audioEngine.js`, `audioAmbience.js` and `audioMusic.js` own the drive, the beds and the score. Gameplay calls `audio.play(id)`, `playCockpit(id)` or `session.playWorldSound(id, intensity, x, y, z)`; add a new sound as an event, never as inline synthesis in `game.js`. `tests/unit/soundDesign.test.mjs` fails if a triggered id has no event or an event names a missing file.
- `assets/audio/fx` and `soundBankManifest.js` are generated by `npm run audio:forge` from `tools/audio/forge/recipes-*.mjs` (needs ffmpeg). Change the recipe and re-render; do not hand-edit either. After removing a recipe, delete its files (the unit test lists orphans).
- Forged loops loop on a window inside the file (`loop: [start, period]`), because MP3 decoders add different delays. Periodic parts must complete whole cycles in the period; only noise parts are crossfaded (`makeLoop`) — an equal-power crossfade of a periodic signal bumps the level.
- Everything timed runs on the audio clock (`context.currentTime`), not `setTimeout`: the offline render (`npm run audio:mix`) drives the real manager through an `OfflineAudioContext` with a stepped clock, and wall-clock timers would cut tails mid-render. Web Audio throws on non-finite AudioParam values; `setEngineTarget` and `playAtDirection` drop them, keep new code behind the same guards.
- Loudness is tuned by measurement: after changing levels, run `npm run audio:mix` (optionally `VR_STEM=music` / `VR_STEM=effects`) and compare against the targets — cruise about −28.5 LUFS (the drive bus is deliberately at 40% since 0.8.2pe; don't raise it to hit the old −25), a dogfight about −18.5 with peaks under −1 dBFS, ambient themes about −30, combat score about −25 (all at the default sliders).
- Earlier revisions of the ambient score were corrected for bright, fast-attack repeating notes ("dings"): station and planet voices stay in the low-mid register with soft attacks. Keep that when adding instruments.
- Audition changes on `/tools/playtest/sound-review/index.html`; `npm run test:browser:sound` is the live check (desktop Chrome runs the graph behind `--mute-audio`, WebKit keeps the context suspended).
- The score is a catalogue: `audioMusic.js` is the director and instrument set, pieces live in `musicSpace.js` (open space), `musicFlight.js` (planet/field/graveyard/stealth/combat) and `musicDocked.js` (docked themes by location), registered in `musicScore.js`. Add music as a new piece object, never as a branch inside the director. Only ids in `APPROVED_PIECES` reach the game; new pieces stay there unapproved until the user approves them on `/tools/playtest/sound-review/music.html`.
- Transitions live in `audioMusic.js`: `transition()` sets fade-out/delay/swell per handover, calm places settle for `SETTLE_SECONDS` before the score follows, and a re-engagement within `COMBAT_MEMORY` resumes the same combat piece. Combat pieces never finish, so leaving combat records the piece in the history (`remember`, combat avoids the last 3); Arena waves call `audio.freshFight()`, which skips the re-engagement resume. `audio.js` holds the combat context for `COMBAT_HOLD_SECONDS` after the last hostile leaves range; don't shorten it back to the danger decay alone (fights then restart the score on every strafing pass).
- Match every new piece to its context's loudness with `npm run audio:mix -- --pieces <id>` (music only; open/planet/field/graveyard about −30, stealth about −32.6, combat about −25.3, docked about −28.8) and set its `trim`. `tests/unit/musicScore.test.mjs` runs every piece through a strict fake Web Audio graph (non-finite values, register cap at C6 for bells/plucks/mallets, node churn).
